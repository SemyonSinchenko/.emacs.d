# AGENTS.md - Emacs Configuration Agent Guidelines

This is an Emacs Lisp configuration repository. It contains **three coexisting
configurations**:

1. **IDE config** (`init.el` + `early-init.el`) - the classic modular
   configuration with `modules/core-*`, `modules/tools-*`, `modules/lang-*`.
2. **Emacs Desktop** (`desktop-init.el` + `desktop-config.el`) - a
   "desktop environment in Emacs": workspaces, terminals, feeds, media,
   AI assistant. All machinery lives in `modules/desktop-*`; all user
   settings live in one file, `desktop-config.el`.
3. **Minimal editor** (`minimal-editor-init.el`) - standalone fast config for
   a daemon + terminal clients (`emacsclient -t`). No LSP/Org stack.

## Running the Configurations

```bash
# IDE config
emacs

# Emacs Desktop (the only supported way; do NOT run it as a daemon)
emacs -q -l ~/.emacs.d/desktop-init.el

# Minimal editor daemon
emacs --daemon --load ~/.emacs.d/minimal-editor-init.el
emacsclient -t /path/to/file
```

## Build/Lint/Test Commands

This is an Emacs configuration, not a compiled project. There is no formal
build process.

### Syntax / Load Checks

```bash
# Batch load check of the Desktop (also exercises module requires;
# module failures are isolated and reported as "[desktop]" messages)
emacs --batch -l ~/.emacs.d/desktop-init.el

# Byte-compile a single module to catch syntax/warning issues
emacs --batch -f batch-byte-compile modules/desktop-keys.el

# Basic load check of a single file
emacs --batch --eval "(setq load-path (cons \".\" load-path))" -l file.el --eval "(message \"OK\")"
```

Notes:

- `desktop-config.el` is intentionally never byte-compiled (it is a plain
  `setq` file loaded by `desktop-init.el`).
- `desktop-init.el` header documents the startup order; module load failures
  are non-fatal and collected in `my-desktop--warnings`.

### Inside Emacs

1. Load a file: `M-x load-file RET /path/to/file.el`
2. Evaluate a buffer/region: `M-x eval-buffer` / `M-x eval-region`
3. Reload Desktop settings after editing `desktop-config.el`:
   `M-x my-desktop-reload-config` (keys, menu, frame look apply live;
   package/module-flag changes need a restart)

### Linting and Formatting

The IDE config uses **Flymake** (not Flycheck) for linting and **Apheleia**
for formatting (both in `modules/lang-lsp.el`).

- Flymake: enabled in `prog-mode` buffers.
- Apheleia: format with `C-x x f` (bound in `core-keys.el`); Python uses
  `ruff`. JSON/JS/TS use 2-space indent (`js-indent-level` etc. in
  `lang-lsp.el`); `indent-tabs-mode` is nil by default.

For external linting:

```bash
emacs --batch -f batch-byte-compile file.el
```

### Running a Single Test

There is no formal test suite. If you add tests (using `ert`):

```bash
emacs --batch -l ert -l your-tests.el -f ert-run-tests-batch-and-exit
```

## Code Style Guidelines

### File Header Convention

All `.el` files should have the standard Emacs Lisp header:

```elisp
;;; filename.el --- Short description -*- lexical-binding: t; -*-

;;; Commentary:
;; Longer description of what this file does

;;; Code:

;; ... implementation ...

(provide 'filename)
;;; filename.el ends here
```

### Lexical Binding

Always include `lexical-binding: t` at the top of every file.

### Imports and Dependencies

- Use `require` for built-in features and repo modules; `use-package` for
  external packages (with `:ensure t`).
- The Desktop loads `desktop-config-defs` first in every machinery module:
  `(require 'desktop-config-defs)`.
- Use `declare-function` to suppress unknown function warnings.
- One-off external packages may use `:vc` (see `eca` in `tools-ai.el`).

### Naming Conventions

- User-facing commands/functions: `my-` prefix (`my-ai-chat`, `my-term-new`,
  `my-ws-switch`, `my-sync-menu`).
- Desktop settings variables: `my-desktop-*` (defined ONLY in
  `modules/desktop-config-defs.el`).
- Kebab-case everywhere. Private/internal helpers use `--`:
  `my-desktop--warn`, `my-keys--apply-context`.

### Keybinding Definitions

- IDE: `defvar` + `make-sparse-keymap` (or `defvar-keymap`, Emacs 29+),
  then `keymap-global-set` / `keymap-set`.
- Desktop: add entries to the `my-desktop--default-keys` table in
  `modules/desktop-keys.el` with a context (`global`, `dired`, `ghostel`,
  `social`, `ai`). User overrides from `my-desktop-keybindings` are applied
  on top (same key = user wins).
- Desktop keys already taken (do not shadow them):
  - `C-c w` - workspace prefix (perspective: switch/create/rename/close,
    buffer overview); `C-x b` / `C-x k` are workspace-scoped.
  - `C-c s` - social prefix (b bluesky, h hackernews, l lemmy, r reddit,
    t telegram); `C-c a` - AI prefix (a chat, o open session, l search,
    g gptel-menu, z Z-AI usage, ...).
  - Top level: ``C-c ` `` (treemacs sidebar), `C-c m` (sync menu),
    `C-c t` / `C-c T` (terminal), `C-c p` (music play/pause),
    `C-c M-w` (copy image at point).
  - `s-*` - roguelike copilot (Super prefix, bound in
    `my-roguelike-keymap`, active only in game terminal buffers via
    `my-roguelike-mode`; see modules/desktop-roguelike.el).
  - The root transient `my-desktop-menu` has no key binding; run it
    with `M-x my-desktop-menu`.

### Use-package Style

```elisp
(use-package package-name
  :ensure t
  :defer t                    ; Lazy load
  :bind ("C-c k" . command)
  :custom
  (var1 "value1")
  :config
  (setup-function))
```

### Error Handling

- Use `condition-case` for robust error handling; the Desktop reports
  non-fatal problems via `(my-desktop--warn "..." ...)` instead of failing
  startup.
- Use `when-let*` / `if-let*` for cleaner conditional logic.

### Formatting and Documentation

- Use Apheleia (`C-x x f`) and standard Elisp indentation.
- Keep lines under 80 characters when practical.
- Add docstrings to all public functions; comment complex sections in
  Russian or English (be consistent; the repo mixes both).

### Defcustom for User Options

```elisp
(defcustom my-module-setting "default"
  "Description for users."
  :type 'string
  :group 'my-desktop)
```

Important for Desktop settings: `desktop-config.el` is loaded BEFORE modules,
and `defcustom` never overwrites an already-bound variable - that is why user
`setq` values in `desktop-config.el` always win. Never hard-code tunables in
machinery code; add a `defcustom` to `desktop-config-defs.el` and read it.

## Emacs Desktop Conventions

- **Settings flow**: `desktop-config.el` (user, plain `setq`) ->
  `modules/desktop-config-defs.el` (schema with defaults) -> machinery
  modules that only read `my-desktop-*` variables.
- **Secrets and machine paths** belong in `desktop-config-local.el`
  (same format, git-ignored). AI API keys come from environment variables
  named via `:key-env` in `my-desktop-ai-backends` - never put keys in
  tracked files.
- **Module flags**: `my-desktop-enable-*` booleans gate optional modules.
  `desktop-init.el` loads modules from a fixed ordered list; each entry can
  be `(module . flag-var)`.
- **Startup order** (see `desktop-init.el` header): hygiene -> environment ->
  load-path -> schema -> user config -> package bootstrap -> modules ->
  first frame (`my-desktop-first-frame-hook` for extra per-module setup).
- **First frame**: workspaces are initialized fresh from
  `my-desktop-workspaces` (no session persistence; save/restore is
  postponed - live processes like terminals/mpv cannot be serialized);
  `my-home-open` opens the Home tab; the sidebar is treemacs scoped
  per perspective. Extra per-module setup goes to
  `my-desktop-first-frame-hook`.
- **No server/daemon** for the Desktop: a stale "desktop" server socket broke
  `server-start` on relaunch; do not re-add daemon support.
- Desktop Org paths (`~/Org`, `~/Org/org-roam/org-files/`) come from
  `my-desktop-org-dir` / `my-desktop-org-roam-dir`.

## Common Tasks

### Adding a New IDE Module

1. Create `modules/xxx-yyy.el` with the standard header.
2. Add `(require 'xxx-yyy)` to `init.el` in the appropriate order
   (core -> tools -> lang).

### Adding a New Desktop Module

1. Create `modules/desktop-xxx.el`; start it with
   `(require 'desktop-config-defs)` and read only `my-desktop-*` vars.
2. Add `defcustom`s for its settings to `modules/desktop-config-defs.el`.
3. Register it in the module list in `desktop-init.el` (use
   `(desktop-xxx . my-desktop-enable-xxx)` if it is optional), and add the
   flag `my-desktop-enable-xxx` to the schema.
4. Add a default (`setq`) line in `desktop-config.el` and, if needed,
   keybindings in `desktop-keys.el`.

### Adding a Keybinding

- IDE: edit the relevant module (`core-keys.el` for global bindings) using
  `keymap-set` / `global-set-key`.
- Desktop: add to `my-desktop--default-keys` in `modules/desktop-keys.el`
  (or document a user override in `desktop-config.el` via
  `my-desktop-keybindings`).

### Modifying Package Settings

- IDE: find the relevant module (`lang-lsp.el` for LSP/formatting) and edit
  its `:custom` section.
- Desktop: packages are bootstrapped in `desktop-init.el`; versions/flags go
  through `desktop-config.el` settings, not ad-hoc edits.

## System Dependencies

`README.org` lists the core, AI, and language-server tools: `git`,
`ripgrep`, `fd`, `curl`, `sqlite3` (org-roam), `unzip`; AI: `aider`,
`lexicon-cli`; servers: `ty` + `ruff` (Python), `jdtls` (Java),
`metals` (Scala), `rust-analyzer` (Rust); `multimarkdown` (Markdown).
The Desktop modules additionally use (all optional, degrade gracefully):
`mpv` (music), `rclone` (sync), `transmission-daemon` (torrents),
`docker` (telega TDLib option), and a SearXNG instance (Desktop AI
web search, see `my-desktop-ai-searxng-url`).

## Files to Leave Alone

- `elpa/`, `quelpa/`, `eln-cache/`, `tree-sitter/`, `jdtls-workspace/` -
  installed packages and caches (git-ignored).
- `custom.el` - generated by Customize (git-ignored).
- `*.elc`, `*~` (backup files), `.cache/`, `ai-sessions/`, `ai-attachments/`,
  `ai-memory.org`, `elfeed/`, `telega/`, `hackernews/`, `eca/`,
  `desktop-config-local.el`, `org-roam.db` - state and caches (git-ignored).
- Editor state (git-ignored): `auto-save-list/`, `savefile/`, `persist/`,
  `url/`, `transient/`, `recentf`, `bookmarks`, `projects`,
  `projectile-bookmarks.eld`, `nov-places`, `tramp`, `lem.plstore`,
  `.aider*` history.
- `openspec/` - archived change proposals (a spec-history folder, not
  runtime config); touch only if the task asks for it.
